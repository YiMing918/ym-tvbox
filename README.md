## 先分清两个地方（新手最容易懵的就是这条线）

这个项目横跨**两个地方**，先把它们分清，后面所有步骤就都通了：

| 地方 | 是干嘛的 | 在本项目里具体指什么 |
| --- | --- | --- |
| **GitHub**（一个放代码的网站） | 存文件、定时干活、发存档包 | 本仓库就住在 GitHub 上：仓库里存着**成品配置**和**合并脚本**；GitHub 的 **Actions**（自动任务功能）每天定时把上游源合并成一份新配置；**Releases**（发行版页面）里放着存档 zip 包供下载 |
| **影视仓 App**（手机上的看片软件） | 真正看片的地方 | 它自己不存片源名单，只认**一个配置地址**：你把地址填进去，它就照着地址去把站点名单拉回来，然后你就能搜片、看片了 |

还有一个词先说清：

- **raw 地址**：一种「直达链接」。普通网页链接点开看到的是排版好的页面；raw 地址点开，看到的就是**文件内容本身**（一大段文字），专门给软件机器读的。本项目的成品配置就挂在一个 raw 地址上，影视仓填的就是它。

把这条线连起来就是全貌：

> **上游源（别人的配置）→ 每天被 GitHub 上的自动任务抓取、探活、合并 → 生成一份成品配置挂在 raw 地址上 → 你把这个 raw 地址填进影视仓 → 影视仓照着它拿到最新站点名单 → 你看片。**

所以：**改东西、看更新状态去 GitHub；看片去影视仓；两者之间只靠那一个 raw 地址连着。** 换地址只换配置，你在影视仓里的收藏、历史记录都不受影响。

## 这是什么、成品里有什么

- **产物就一个文件**：`peter_tvbox_pro.json`（JSON 是一种给软件读的文本格式）——一份给 TVBox / 影视仓类应用读取的配置，装着站点、直播源、解析线路三类东西。你（或你的应用）真正要用的就是它；仓库里的其余文件，都是为「每天自动生产它」服务的。
- **sites（站点）**：219 条（上限约 220，随上游每日浮动）——采集站（走资源站接口的）约 15 个 + 爬虫站（走解析规则抓取的）约 205 个，覆盖影视 / 4K / 动漫 / 短剧 / 体育 / 音乐 / 少儿 / 直播 / 网盘等类目（逐类名单见下方「收录内容」；精确数字以仓库内 `peter_tvbox_pro.json` 本体为准）。
- **lives（直播源）**：8 个直播频道列表源。
- **parses（解析线路）**：40 条解析 / 嗅探线路，播到需要解析的地址时由应用调用。
- **合并保护（异常时保留上一版）**：可用上游少于 3 个、合并后站点少于 120 个、或比上一版骤降超过 20% 时，本轮直接放弃提交、保留上一份可用配置；单个上游临时不可用也会自动跳过，不拖垮整轮。采集接口与站点依赖文件都采用三态探活：只有连续两次确认失效才剔除，临时故障、403 / 限流等不确定结果一律保留，避免自动任务的网络环境与你的网络不一致时误删。

先说结论：**日常使用什么都不用下载**，用的是一个网址（raw 地址）。只有要备份存档时才去 Releases 下包。

| 文件 | 用途 | 谁需要 |
| --- | --- | --- |
| （不用下文件）配置地址 `https://raw.githubusercontent.com/YiMing918/ym-tvbox/main/peter_tvbox_pro.json` | 填进影视仓直接用，每天自动是最新版 | 所有人（方式一） |
| `ym-tvbox-deploy-*.zip`（在 Releases 里） | 整仓**存档 / 迁移快照**：哪天想把整套东西搬走、或离线留底时用；解压能看到成品 JSON + 合并脚本 + 工作流文件 | 想留底 / 迁移的人 |
| `SHA256SUMS.txt`（在 Releases 里，和 zip 放一起） | 校验文件：里面写着 zip 的 SHA-256 指纹，下载后可核对文件有没有损坏或被调包 | 下了 zip 的人 |
| GitHub 自动生成的 **Source code (zip / tar.gz)** | 这是 GitHub 给每个发行版自动附的源码快照，**不是部署包**，别下错 | 不用下 |

注意：这个仓库是「配置文件」不是程序，**没有服务器部署一说**，也不需要域名、不花钱。

## 使用方式一：直接用现成配置（推荐）

**优势**

- 零门槛：不用注册任何账号，不用碰代码，复制一个地址填进 App 就完事。
- 永远是最新版：原站每天自动更新，你这边打开 App 就能拿到新名单，什么都不用管。
- 出问题有人（作者）维护，你只管用。

**劣势**

- 不能自己改：想加 / 删某个源、换上游名单，做不到——名单是原站定的。
- 依赖原站：地址是别人仓库的，原站若改名、删仓，地址会失效（真到那天改用方式二）。
- 更新时间和内容由原站的自动任务决定，你不能手动催更。

**手把手步骤（以影视仓 App 为例）**

1. 先把配置地址准备好（长按下面这行复制，注意**从 h 到 n 完整复制，别多空格、别少字符**）：

   ```
   https://raw.githubusercontent.com/YiMing918/ym-tvbox/main/peter_tvbox_pro.json
   ```

   国内网络拉这个地址很慢或打不开时，用加速地址（内容完全一致）：
   ```
   https://gh-proxy.com/https://raw.githubusercontent.com/YiMing918/ym-tvbox/main/peter_tvbox_pro.json
   ```

2. 打开手机上的**影视仓** App → 点右上角的**设置（齿轮图标）** → 找到**「配置地址」**那一栏点进去（不同版本菜单名字可能略有差别，认准「配置」二字）。
3. 把输入框里原有的地址**全选删掉**，再把第 1 步复制的地址**粘贴**进去 → 点**确定 / 保存**。
   - 做到这里你应该看到：App 弹出「加载中」之类的提示，开始转圈拉取。
4. 等它加载完，回到 App **首页**。
   - 做到这里你应该看到：首页出现站点分类，下面有一排站点名字（金牌影视、厂长影视之类）——看到名单就是填对了。
5. 随便点开一个站点。
   - 做到这里你应该看到：能刷出影片海报 / 列表——能刷出来就是真的能用了，全部完成，以后打开 App 直接看就行。

**填完没成功的先看这里**（更多问题见文末「常见问题」）：

- 一直转圈 / 提示加载失败：先检查手机网络；再把地址删掉重粘一次（十次有八次是复制时多了空格或少了一截）；还不行就换上面那条加速地址。
- 换了新地址但还是旧名单：在设置里重填一次配置地址，或把 App 彻底关掉再打开（App 有缓存，不会自动实时刷新）。
- 某个片子播不了：换一个站点 / 换一条解析线路再试，这是上游的问题，不是地址填错了。

## 使用方式二：Fork 一份自己跑

**优势**

- 地址是你自己的：不依赖原站，原站没了也不影响你。
- 能自己改源：上游名单在你手里，想加想删自己说了算。
- 更新自己跑：你自己仓库的自动任务每天合并，不用等原站。

**劣势**

- 门槛高一点：要注册 GitHub 账号，要点几步开启自动任务（下面一步步写，照着做就行）。
- 要自己照看：自动任务被停用、某轮失败，要自己去 Actions 页看一眼。
- 原站以后改进了合并脚本，你要手动点一次「同步」才能跟上（内容更新不用管，每天自动；只有脚本逻辑更新才需要同步）。

**手把手步骤**

1. **注册 / 登录 GitHub**：打开 [github.com](https://github.com)，没账号点右上角 **Sign up** 按提示注册（要一个邮箱），有账号直接登录。
2. **Fork（复制一份仓库到你账号下）**：打开本仓库页面 → 点右上角 **Fork** 按钮 → 点 **Create fork**。
   - 做到这里你应该看到：页面跳到你自己账号下的同名仓库，地址变成 `github.com/你的用户名/ym-tvbox`。
3. **启用 Actions（最关键的一步，不做就永远不会自动更新）**：在你自己的仓库页 → 点顶部 **Actions** 标签 → 如果看到一段提示文字，点里面的 **I understand my workflows, go ahead and enable them**（启用工作流）按钮。
   - 做到这里你应该看到：Actions 页左侧出现工作流名单，其中有 **Update TVBox config**。
   - 为什么要手动开：GitHub 的平台规则——Fork 来的仓库默认关掉自动任务，对所有仓库一视同仁，不是代码有问题。本工作流**零密钥**（上游全是公开源），启用后不用再配任何东西。
4. **先手动跑一轮验货**：在 Actions 页左侧点 **Update TVBox config** → 点右侧 **Run workflow** 按钮 → 分支保持 **main** → 再点绿色的 **Run workflow** 确认。等几分钟，刷新页面。
   - 做到这里你应该看到：这次运行前面是**绿勾**（成功）；黄色感叹号是「保护性跳过更新」也算正常（见「自动更新」一节）；**红叉**才是真失败，点进去能看日志。
5. **确认产物生成**：回到仓库主页，看 `peter_tvbox_pro.json` 文件后面的更新时间是不是刚刚。
   - 是刚刚 = 你这条生产线通了。
6. **拿你自己的配置地址**（二选一，把 `你的用户名` 换成你的 GitHub 用户名）：
   - **raw 直达**（更新最及时）：`https://raw.githubusercontent.com/你的用户名/ym-tvbox/main/peter_tvbox_pro.json`
   - **jsDelivr 镜像**（国内拉取更快更稳，但镜像有缓存，刚更新完可能晚几小时才刷新）：`https://cdn.jsdelivr.net/gh/你的用户名/ym-tvbox@main/peter_tvbox_pro.json`
7. **填进影视仓**：照「使用方式一」的第 2 步起做一遍，只是把地址换成第 6 步你自己的那条。
   - 做到这里你应该看到：首页刷出站点名单——完成。此后每天北京时间 05:30 自动更新，你什么都不用管。

**想改源的人看这里**：上游名单写在 `merge.py` 里（从 `SOURCES = [` 开始的那一段，越靠前的源优先级越高）。在 GitHub 网页上点开 `merge.py` → 点铅笔图标（编辑）→ 照着现有条目的格式增删地址 → 拉到页面底部点 **Commit changes** 保存。改完可以去 Actions 页手动 Run 一轮立刻验证。没有把握就别改这一段——格式写错整轮合并会失败（失败了也不会弄坏现有成品，上一版会保留）。

## 自动更新

- **更新什么**：每天把 6 个上游源重新抓一遍，逐个站点探活（测它还能不能打开），死的剔除、新的合并进来，重新生成 `peter_tvbox_pro.json`。你影视仓里看到的名单就是这么来的。
- **谁触发、几点跑**：GitHub Actions 里的 **update** 工作流。原站是「双保险」：工作流文件里自带定时（每天 UTC 21:30 = 北京时间 **05:30**），另有站长的外部调度器每天也会触发一轮兜底。
- **Fork 的人改时间 / 只靠自带定时**：打开你仓库的 `.github/workflows/update.yml` 文件，找到 `cron: '30 21 * * *'` 这一行——这就是定时设置（格式是「分 时 日 月 周」，且用的是 UTC 时间，要换算成北京时间减 8 小时）。改完保存即生效；不改就是每天北京时间 05:30 自动跑，不需要任何外部调度器。
- **严格 jar 政策（重要，解释「为什么站点比上游少」）**：爬虫站点要靠一个叫 jar 的脚本文件干活（影视仓实际会执行它）。规则定死：**走 http 明文传输、又没有 md5 校验值（一种文件指纹，用来验证文件没被人半路调包）的 jar，一律自动剔除，带这种 jar 的站点跟着下线**。明文 + 无指纹 = 半路被人换成恶意文件你都发现不了，这是防投毒。所以成品里的站点数比上游原始名单少一截，是**故意的**，不是漏抓了。
- **安全熔断**：可用上游少于 3 个、合并后站点少于 120 个、或比上一版骤降超过 20% 时，本轮放弃提交、保留上一份好配置，并以黄色警告收场——所以偶尔会看到「今天没更新」，多半是这个保护在起作用，不是坏了。
- **在哪看最近一轮成没成**：仓库页 → **Actions** → 左侧 **Update TVBox config** → 右侧列表第一条就是最近一轮：**绿勾 = 成功**，点进去拉到日志末尾找 `[done]` 那行，写着这一轮最终收了多少站点；**红叉 = 失败**，点进去看哪一步变红。
- **失败了怎么办**：多数是某个上游临时抽风，不用管，第二天自动重跑；想立刻重试就点 **Run workflow** 手动跑一轮。成品文件有熔断保护，失败轮次不会把好配置覆盖掉。

## 探活：怎么确认配置还活着

没有专门的探活网页，用这三个手动验法，任意一个通过即是活的：

1. **浏览器打开 raw 地址**：在手机或电脑浏览器里打开配置地址。
   - 做到这里你应该看到：一大段以 `{"spider":` 开头的密密麻麻的文字——这就是成品文件本身，**能打开 = 活着**；若显示 404，多半是地址抄错了（Fork 的人检查用户名那段是不是自己的）。
2. **看成品文件的更新时间**：仓库主页找到 `peter_tvbox_pro.json`，看它后面的提交时间是不是今天凌晨前后——是今天 = 生产链正常。
3. **看 Actions 最近一轮**：绿勾在 = 自动任务在正常干活（看不懂日志没关系，认绿勾就行）。

注意分清：**探活验的是仓库这条生产线**；某个具体站点在影视仓里打不开，是那个站点的上游问题，等一轮更新通常会修正或剔除，不代表配置死了。

## 保活：它靠什么一直运转

- **GitHub 有个 60 天规则**：仓库长期没有任何活动，GitHub 会把定时任务**停用**（防僵尸仓库占资源）。停用后配置就不再每日更新了。
- **本仓库的保活办法**：update 工作流里自带**心跳**——每次运行时检查仓库多久没提交了，超过 25 天没动静就自动补交一个 `.heartbeat` 小文件，让仓库始终「有活动」，定时任务不会被停。原站另外还有外部调度器每天触发，就算定时被停，调度器那一轮照样跑（双保险）。
- **Fork 的人要注意**：心跳步骤在工作流里自带，你 Fork 后启用 Actions 就一并有了；万一还是被停用了，去 **Actions 页**点顶部横幅里的**启用**按钮即可恢复，不用改代码。
- **仓库长期不用会怎样**：成品文件不会被删，raw 地址一直能打开，只是名单停在最后更新那一天越来越旧；哪天想恢复，启用 Actions 再手动 Run 一轮就满血了。

## 目录结构（每个文件是干什么的）

| 文件 | 干什么的 |
| --- | --- |
| `peter_tvbox_pro.json` | **成品配置**，影视仓真正要读的就是它。自动生成的，别手动改（改了第二天也被覆盖） |

## 常见问题

**Q：配置地址到底填哪个？**
A：优先填 raw 直达地址；国内网络拉取缓慢时用加速地址（gh-proxy 那条），两份内容完全一致。

**Q：地址粘贴进影视仓了，一直转圈 / 提示加载失败怎么办？**
A：按这个顺序排查：① 手机网络正常吗（换个网页试试）；② 把地址全选删掉重新粘贴一遍——最常见的原因是复制时多了空格或少了一截，地址必须一字不差；③ 换加速地址试试；④ 彻底关掉 App 再打开重填。

**Q：加载成功了，但点开站点刷不出影片 / 片子播不了？**
A：地址没问题（名单都出来了），是那个站点自己的上游在抽风。换一个站点，或播放时换一条解析线路；等下一轮自动更新通常会修正或剔除。

**Q：更新了但应用里还是旧名单？**
A：在影视仓里重新读取一次配置地址（设置里重填 / 保存一次），或彻底重启 App。App 侧有缓存，不会实时刷新。

**Q：为什么今天打开站点变少了 / 没变化？**
A：探活会剔除失效站点，数量小幅波动正常；jar 政策也会让带不合规 jar 的站点下线。若上游大面积失效触发了安全熔断（可用上游少于 3 个或合并站点少于 120 个），本轮会自动放弃更新、保留上一份好配置，所以会显得「没变化」——这是故意的保护，不是坏了。

**Q：直播频道打不开？**
A：直播源稳定性普遍弱于点播源。先换同一栏里的其他直播源 / 线路；整栏都不行多半是上游在维护，等更新。

**Q：有些源在国内网络直连打不开？**
A：部分境外源需要你自己的代理环境才能连通，这是网络问题，不是配置问题。配置本身完全免费，不需要服务器、不需要域名。

**Q：网盘类站点要登录的是谁的账号？**
A：你自己的。你在应用里登录你自己的网盘账号才能用那些条目，本仓库不含任何人的账号凭证（见下方隐私）。

**Q：Fork 了，但 Actions 页是灰的 / 没有自动更新？**
A：Fork 仓库默认关闭 Actions，去 Actions 页点启用按钮（见「使用方式二」第 3 步）。启用后先手动 Run workflow 跑一轮验证。

**Q：Fork 后跟原站有什么不同？**
A：内容更新（站点名单）由你自己的工作流每天跑，天然独立；逻辑更新（合并脚本改进）要去你仓库主页点 **Sync fork** 手动同步原仓库代码。两边探活时刻的上游状态不同，名单有几个站点的细微差异属正常。

**Q：自动更新停了好几天，怎么恢复？**
A：先看 Actions 最近一轮是不是红叉（红叉点进去看日志，多数是上游临时不可达，手动 Run 一轮即可）；再看是不是被 GitHub 的 60 天规则停用了——Actions 页顶部横幅点启用即可。本仓库有心跳保活，正常不会被停。

**Q：GitHub 定时任务延迟了几小时，配置日期差一天正常吗？**
A：正常。GitHub 的定时任务高峰期偶尔延迟，差几个小时到一天都不算故障，成品文件看更新时间即可判断。

- 本仓库只有公开聚合的接口配置与合并脚本，**不含任何个人账号、密码或 Cookie**。
- 配置里「我的 XX 网盘」类条目是空白占位，使用者需在应用内登录**自己的**网盘账号才能用，与本仓库作者无关。
- 自动更新脚本只抓取公开上游配置并探活，不收集任何使用者数据。
- **关于第三方 jar（请知悉）**：爬虫站点依赖上游作者发布的 spider jar 文件（应用实际执行的代码），本配置只是转载引用、无法审计其内容。合并脚本已做的治理：带 md5 固定值的 jar 按「一个地址只认一个 md5」归一；站点自带的 **http 明文且无 md5** 的 jar 直接剔除（明文传输又无完整性校验，可被无声替换）；少量 https 无 md5 的 jar 靠 TLS 本身防篡改。继承自上游整仓 spider 的 jar 同样在剔除之列（2026-11-14 站长拍板严格执行：俊哥 / 小盒子 / 二月红等整仓接口因其 spider 为 http 无 md5 而下线，日志中逐条以 `[jar-drop]` 标明）。介意执行第三方代码的话，请只用采集站（type 0/1，不加载 jar）。
